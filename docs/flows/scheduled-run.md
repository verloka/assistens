# FDD-003 — Scheduled run with safe desktop preemption

Status: Draft

## Trigger / Outcome
- Initiator: the scheduler reaches a persisted occurrence time.
- Outcome: exactly one corresponding run is created or the occurrence is skipped/deferred, without unannounced GUI interference.

## Inputs
- Task definition, interval/timezone, misfire policy, recurrence/occurrence key, GUI requirements, countdown/idle policy.

## Outputs
- Durable run status, skip/deferral reason, available result and delivery to configured channel.

## Flow
1. Calculate the next due occurrence in configured timezone, recording a unique occurrence key.
2. Avoid duplicate runs and overlapping occurrences of the same schedule.
3. For MCP-only work, proceed independently of the GUI lease; if later GUI is needed, enforce FDD-002 at that first tool call.
4. For GUI work, warn with countdown; apply `AskEveryTime`, `StartWhenIdle` or `StartAfterCountdown` policy as configured.
5. Honor manual skip/delay, user activity, user Take Control, locked Windows session, and misfire policy on restart.
6. Persist outcome, recalculate next occurrence and invoke FDD-006 only for allowed notifications.

## Validations
- The owner can create/edit all four recurrence modes, select timezone/model/misfire policy, inspect future triggers and schedule-specific history, and disable/re-enable without deleting the schedule or its runs. Saving uses the loaded revision; a concurrent dispatcher/edit requires explicit reload instead of silently overwriting it. Disabling affects future admission, not an already committed run.
- At new desktop acquisition, scheduled work waits behind an explicitly presented warning naming the task. A 15-second countdown starts only after presentation. StartAfterCountdown may proceed after that interval; AskEveryTime requires Start now. StartWhenIdle remains the default and must not auto-proceed when idle evidence is absent. Skip once terminates this waiting occurrence only, Defer waits for explicit Start now, and Disable schedule disables future admission and skips the waiting occurrence. Closing the warning defers; it never grants access. Pause/cancel or changed configuration invalidates stale warning decisions.
- StartWhenIdle auto-admission requires a currently available interactive desktop, at least 60 seconds of session input idle and the presented 15-second warning; recheck immediately after the durable wait transition before acquisition. Unknown/failed idle readings cannot authorize automatic access; locked/unavailable desktop cannot be bypassed by Start now. Explicit Start now may override busy idle on an available desktop. System input idle is independent from model/tool progress and is not a human-only or in-run activity detector; injected events can also reset it.
- Schedule enabled; timezone valid; occurrence unique; active/idle Windows state; user priority; execution and communication permissions.
- Recurrence data supports only once, positive whole-minute interval, daily local time and explicit weekdays. Invalid or conflicting fields/timezones are refused before storage. Store UTC occurrence timestamps plus the chosen timezone; interval cadence is anchored to creation. Schedule edits use an expected version; saving unchanged cadence does not silently skip an already due occurrence.
- Scheduled submission uses the existing durable external-trigger key for exact ScheduleId/UTC occurrence. Commit the run before advancing the schedule with version/occurrence checks; if interrupted between those commits, find the original run and advance without submitting another execution. One active run per schedule holds later occurrences; default overdue handling coalesces to one run rather than replaying missed intervals in a burst.
- The run creation transaction checks the current enabled schedule/version/occurrence and task inputs, so disabling or editing a schedule before admission cannot submit an obsolete task. Already committed runs retain their immutable snapshot and independent cancellation controls.
- Misfire defaults to RunOnce. Skip records a terminal skipped occurrence without queueing execution; lateness up to one minute is ordinary scheduler jitter. CatchUp is explicitly bounded (1..10 runs per persisted recovery batch, default 3), allowed for calendar recurrences or intervals of at least one hour. Preserve its budget/window across restart and unchanged-cadence edits; after the budget, advance beyond the current time. Calendar gaps skip the missing local occurrence and repeated wall time uses its earliest UTC instant once.

## Invariants
- A scheduled GUI task cannot silently steal the keyboard during active user work when idle policy is enabled.
- Missed periodic checks are not blindly replayed in a burst; default policy is RunOnce.
- One occurrence cannot result in two independently executing runs.

## Failures / Side Effects
- Offline/locked screen, overlap, unsupported credentials and user skip produce explicit outcomes.
- Persisted schedule and run-event writes; possible external reads and notifications.

## Dependencies
- Flow: FDD-001 — run lifecycle.
- Flow: FDD-002 — desktop control.
- Flow: FDD-006 — notification delivery.
