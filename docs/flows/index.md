# Business Flow Index

A flow is one **complete user-observable outcome**, not a class, tool, API or database table.

- `Discovered`: possible flow, not traced; documentation optional.
- `Draft`: proposed or traced flow, **not human-approved**.
- `Active`: explicitly human-approved, authoritative behavior contract.

**Initial state:** all entries below are **design Drafts** derived from `docs/DEVELOPMENT_PLAN_v1.1.md` and the agreed project scope. No application implementation or passing test is claimed. They are **not Active** until the user explicitly approves them. Update source references and `[test: ...]` links as development adds code and verified tests.

## Unmapped Entry Points

- `src/PersonalAgent.Core/Application/ChannelMessageRouter.cs` maps to FDD-006 and reverse FDD-001/003/007 plus FDD-005 boundaries: versioned neutral adapter envelopes, bound channel/connection identity, explicit sender/route policy, common plain task submission/external dedup and capability-aware one-attempt outbound routing. App DI defaults to no adapters/no approved peer bindings; no network worker or model/tool grant is enabled. ChannelContractTests covers fake Telegram/second adapter with actual App/Core/SQLite; real Telegram/outbox/approval callbacks remain subsequent scope. All Draft.
- `ChannelOwnershipPolicy`/`ChannelOwnerCommands` map to FDD-006/FDD-005: metadata-only Pending pairing, explicit local owner CAS review, exact peer allowlist and fresh owner authentication before task controls/approval. No body/token can approve a binding or supply actor identity. ChannelOwnershipTests uses real SQLite/Core/MAF/local MCP with synthetic peers; WPF review101 and Telegram callback099 remain separate, all Draft.

- `src/PersonalAgent.App/ScheduledDesktopWarningWindow.xaml` and App-started ScheduledDesktopWarnings map to FDD-003/FDD-002: nonactivating local warning, 15-second presented countdown, explicit start/skip/defer/disable. Headless hosts never auto-show windows, close defers, and unknown idle evidence cannot auto-start StartWhenIdle. DesktopAccessCoordinator preserves deny-by-default and local takeover after the async callback. Actual unshown XAML/SQLite/fake native evidence is ScheduledDesktopTests; no new flow, all Draft.

- `src/PersonalAgent.App/SchedulesWindow.xaml` is opened explicitly from MainWindow and maps to FDD-003 (reverse FDD-007 and dependencies FDD-001/002/006): create/edit/enable/disable, persisted future triggers and schedule-specific history. Uses existing versioned schedule storage and run identities; does not grant tools or desktop access. SchedulesUiTests covers unshown XAML/SQLite; countdown/idle and delivery remain separate. All Draft.

- `src/PersonalAgent.App/ApprovalsWindow.xaml` maps to FDD-005 and reverse FDD-001/004/007: explicit nonmodal owner review of exact operation, destination, arguments and expiry; deliberate Approve or Deny. Current local Windows SID is trusted identity; opening/closing does not decide or take focus automatically. ApprovalsUiTests covers actual XAML/SQLite/local MCP decisions; no new flow is needed and all remain Draft.

- `src/PersonalAgent.App/McpConnectionsWindow.xaml` is opened by the MainWindow MCP header and maps to FDD-004: persisted owner destination/credential configuration, explicit connect/discovery, tool schema/classification/allowlist review, disconnect/remove. Loading saved settings does not connect. Per-run approval remains FDD-005 and default model task tool exposure stays closed pending production policy integration. Actual XAML/SDK/SQLite/DPAPI evidence: McpConnectionsUiTests; no separate flow needed.
- PA-074 deterministic hybrid evidence for FDD-001/002/004: HybridMcpGuiTests composes one actual App/Core/MAF/registry/SQLite run with a loopback Jira MCP and in-memory Teams/native GUI. Both tool orders, late desktop admission, cancellation and UI/durable timeout outcomes pass. Physical idle detection and corporate/notification acceptance remain separate; no production tool exposure or flow approval is implied.

- `src/PersonalAgent.App/MainWindow.xaml` includes host diagnostics and the task Dashboard. Submit/pause/resume/cancel, ModelsPanel and explicit conversation continuation map to FDD-001 (with pause referencing FDD-002 and neutral follow-up referencing FDD-006). Startup uses the local fake; explicit saved-profile selection routes text tasks to OpenAI/Anthropic. Computer/MCP/channel tools are not exposed through this path. No separate diagnostic flow is warranted.
- After implementing each milestone, inspect new WPF actions, Telegram commands, scheduled triggers, MCP tools and background workers. Record any entry point not covered by an indexed flow here before closing the task.
